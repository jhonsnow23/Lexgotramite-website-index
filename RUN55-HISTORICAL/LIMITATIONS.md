# Limitations and remaining acceptance criteria

1. Primary live acceptance not achieved here: no API credential in sandbox, direct BOE API DNS unavailable. Install and run the new workflow. Do not treat 211 passing tests as evidence of actual legal approval. Model access and exact real response behavior remain to be verified.
2. New pathway covers six categories structurally, but only non-lucrative residence has a full candidate/review/repair replay with archived evidence. Other categories have profile/retrieval/dossier checks, with no archived Article 160 for children. Legislative update and comparison article types have explicit reviewer requirements but no full scenario validation or special prior-version retrieval implementation. All six types are not live tested.
3. Claim text is model-proposed and provenance-checked before the internal candidate. It is not independently semantically certified before rendering; independent legal review of the complete article is the binding semantic gate. This deliberate design avoids the repeated pre-draft proposal blockage. An automated pass is not human legal certification.
4. The BOE version mechanism is reused and can identify dated text, but cannot independently certify legal vigency. Extraordinary regularisation uses existing retrieved official publication/guidance as contextual evidence; current consolidated disposition-level retrieval is not separately implemented in the new path. Reviewer must reject if current operative basis is insufficient. New LO cross-reference handling is limited to the two configured BOE document IDs. New guidance discovery is bounded to the existing vetted registry; targeted retrieval is currently article-based, not arbitrary new official web/PDF discovery.
5. Within-run source/index caching, state and candidate checkpoints are implemented. Automatic cross-run resume, persistent legal cache with revalidation, and merging bootstrap outcomes into GSC topic history are not implemented. Existing normal GSC history remains. The ordinary workflow handles a single selected topic; multi-topic fallback is in the new bootstrap workflow. Bootstrap seeds are editorial, not verified demand. Explicit target selection does not bypass safeguards.
6. Model repair checks are semantic and imperfect; all prior defects are explicitly included for binding review, exact repeated rejected candidate hashes are blocked, and no contradictory verdict is coerced. No human reviewer has reviewed these artifacts. Independent review means a separate model call, not legal certification.
7. Full historical test suite remains non-green (17 failures/errors + 1 skip). One genuine safety defect fixed, others categorized in ROOT-CAUSE-ANALYSIS. No prior tests were modified to manufacture success. The exact normal workflow suite is green.
8. Git compatibility verified against reconstructed local supplied baseline, not remote main. Two old publisher workflows in supplied snapshot had scheduled write/push steps; the package disables them in code. Remote state and other external deployment/publishing integrations not inspected. Actions artifacts access depends on repository permissions; never store personal case data.
9. API budget is conservative estimate, not guaranteed maximum charged by provider. Real wall-clock and API usage remain unverified. Workflow timeout is final hard bound.
10. No existing public website files changed. No article is automatically published. Human review remains mandatory.
